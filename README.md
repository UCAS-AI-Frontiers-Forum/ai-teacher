# AI Teacher｜Codex 插件 V0.2.0

**你可以只提出一个目标；Teacher 主动提问、用样稿和小试挖掘尚未说清的需求，承担技术选择、工作流搭建、自检与修复，尽量减少你的解释、监督和接管负担。** 用户不必先认识模型、skills、plugins 或框架。

项目目的：把熟练使用 AI 者的判断方法，转化为普通人可调用的能力。哪些环节交给 AI、如何拆解模糊目标、组织材料和选工具、修复失败并检查结果，首先由 Teacher 承担；不以用户先学会这些能力作为产品有效的前提。工作流是因人因任务生成的产物。减少监督是待验证目标，仍保留必要的意图、授权与领域判断。

日常入口是 `$ai-teacher`，不预设六种科研任务或通用课程。当前包含主动目标发现机制、随包辅助 skill `$work-memory` 和深度案例/对照试用协议；目前是技能指引与记录机制，尚未证明能降低真人使用负担。

## 它怎样工作

1. 从用户的自然目标出发，主动选择关键问题、样稿或小试，发现用途、约束和瓶颈；明确区分已确认信息、推断与待确认项。
2. 查询并理解相关技术，记录来源、版本、适用条件和实际试验；比较保持现状。
3. 在当前授权内搭建流程、推进执行、自检并有限修复；给人最短操作说明，给执行 AI 完整任务书。技术判断尽量自行承担，必要时带具体证据交回人。
4. 按标准试用、检查新材料上的复用，记录结果质量、目标误解和人工负担；按证据更新版本。不能靠少提问、少检查或隐去失败宣称改善。

可以只提出一个改进，也可以建议不换工具。不会把固定模板、技术新闻或未经验证的推荐当成效果。

## 从记忆理解工作

随插件安装的 [work-memory](plugins/ai-teacher/skills/work-memory/SKILL.md) 提取四类任务相关信息：工作流程、反复问题、历史取舍和近期变化。AI Teacher 在需求发现前按需使用，也可单独说“用 `$work-memory` 帮我整理本次任务的相关记忆”。

优先使用宿主已提供的记忆，只在当前允许范围内按需检索；每条保留依据、日期、适用范围和待确认项，没有记忆照常推进。不自动读完个人历史、不改写宿主记忆，也不内置跨宿主同步或采集服务。它帮助减少重复解释，不能把历史偏好当成本次目标或操作授权。

## 安装与第一次调用

按 Codex 标准插件方式安装，在终端运行：

```bash
codex plugin marketplace add airesearchjishengyin/ai-teacher --ref main && codex plugin add ai-teacher@ai-teacher-local
```

安装后在 Codex 新建聊天，选择 **AI Teacher**，直接说出目标：

> 帮我比较实验结果，方便决定下一步做什么。请主动问出你需要的信息，先做一小段让我判断是否符合目标，再搭建和检查流程。只使用公开/模拟材料。

也可以只说“我想让组会准备省心一些”。不必先定位瓶颈或写完整需求，Teacher 应主动发现关键缺口；信息足以可逆小试就推进，再从反馈继续对齐。先做一段，不必自动化整个科研过程。

无需克隆仓库、下载 ZIP 或运行本项目的安装脚本。插件由 Codex 管理，可在插件页查看、启用和卸载；若插件页未刷新，重启 Codex 后再新建聊天。记录工作流状态时会使用 Python 3.10+，由 Teacher 检查运行环境。

卸载：

```bash
codex plugin remove ai-teacher@ai-teacher-local
```

安装流程遵循 [Codex 官方插件说明](https://developers.openai.com/codex/plugins)；当前仓库通过 GitHub 插件源分发。

## 持续更新到底指什么

状态存于项目 `ai-teacher-work/`：匿名任务档案、目标发现记录、带来源与期限的能力卡、工作流版本、证据与反馈。每次相关调用会检查并处理待复核项，用户无需先提供新工具名称；没有收益则保留现有方案。

**不是模型权重训练，也不是已启动的后台监控。** 未打开会话时不会自行上网；定时追踪须另行明确授权并配置宿主调度。本包没有预装“最新技术全库”，首次按需研究；没有联网能力会如实说明。

不绑定付费 API，无遥测、自动训练或反馈上传。Codex/联网工具仍可能收费及传输上下文。企业私有原始数据、代码、凭据不进入试用；未公开研究材料先确认权限和数据去向。本包不是保密沙箱。

## 试用与边界

- [TRY.md](TRY.md)：从身边研究生同学的自然目标开始深度试用。
- [EVALUATION.md](EVALUATION.md)：开发案例→方法蒸馏→新任务对照，含普通 Teacher 提示词及记录模板。两组模型/工具一致，以质量达标前提下的人工总负担比较。
- [DESIGN.md](DESIGN.md)：对原 PRD 的取舍和本版实现范围。
- [FEEDBACK.md](FEEDBACK.md)：自愿记录具体发现、成功/失败和监督接管负担，不自动收集完整聊天与私有材料。
- [VALIDATION.md](VALIDATION.md)：实际验证了什么，哪些尚未验证。

脚本校验状态、版本、过期能力和证据路径，不会自动选出最优流程，也不能证明模型判断正确。它服务于 AI teacher，而不是把决策替换成固定规则。包内演示均为合成数据，不是用户效果。
